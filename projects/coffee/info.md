# Coffee — консольный симулятор кофемашины

Изучительная программа на Go. Цель — закрепить структуры, слайсы, `map`, интерфейсы, указатели, обработку ошибок и Git-флоу. Без горутин, каналов и sync-примитивов.

## Обзор

Интерактивный REPL-интерфейс с приглашением `> `. Все команды вводятся по одной строке. Состояние (остатки ингредиентов) хранится в памяти процесса и персистируется в файл `stock.txt` при выходе через команду `exit`.

## Структура проекта

```
coffee/
├── go.mod                  # модуль coffee (Go 1.26.5)
├── info.md
├── cmd/
│   └── coffe/
│       └── main.go         # точка входа, REPL, обработка команд
└── internal/
    └── domain/
        ├── errors.go       # пакетные ошибки (Err*)
        ├── machine.go      # Machine (stock, recipes, orders, revenue) + Brew/Stats
        ├── recipe.go       # Recipe и DefaultRecipes
        ├── stock.go        # Stock (map[string]int) + Save/Load
        └── storage.go      # интерфейс Storage
```

## Запуск

```sh
go run ./cmd/coffe
```

## Команды

| Команда | Действие | Вывод успеха |
|---|---|---|
| `help` | Вывести справку, выйти | `справка` |
| `menu` | Список напитков и цен | `напиток цена` (по строке) |
| `stock get` | Остатки ингредиентов | `name = value` (по строке) |
| `stock add <ингредиент> <количество>` | Прибавить к остатку (qty >= 1) | `ok` |
| `stock set <ингредиент> <количество>` | Установить точный остаток (qty >= 0) | `ok` |
| `brew <напиток> --pay <сумма>` | Приготовить напиток | шаги через ` -> ` |
| `stats` | Агрегаты продаж | `orders = n revenue = sum` |
| `exit` | Сохранить склад и выйти | `Bye` |

Порядок в `menu`, `stock get` зависит от обхода, иденичных по `map`; порядок не гарантируется, так как Go.

## Рецепты (по состоянию в коде)

| Напиток | Цена | Ингредиенты | Шаги |
|---|---|---|---|
| espresso | 150 | beans=8, water=30 | grind, tamp, brew 25s |
| americano | 180 | beans=8, **water=150** | grind, brew 25s, add water |
| latte | 220 | beans=8, water=30, milk=150 | grind, brew 25s, steam milk, mix |

> Примечание: в исходном ТЗ у `americano` water=120, в коде — 150.

## Ошибки и коды выхода

| Ситуация | Вывод | Выход |
|---|---|---|
| Нет аргументов у `stock`/`brew`, пустая или неизвестная команда | `usage` | 2 |
| `brew` без флага `--pay` | некорректные параметры | 1 |
| `brew` неизвестного напитка (flatwhite) | напиток не найден | 1 |
| Недостаточная оплата | недостаточно денег | 1 |
| Не хватает ингредиентов | не хватает ингредиентов | 1 |
| `stock` неверный ингредиент/количество, неверный формат | некорректные параметры | 1 |

(0 у `help`. Код выхода устанавливается для `os.Exit`.)

## Ключевые особенности кода

- `Machine.GetRecipes` возвращает значение (копию `map`); мутабельные методы (`Brew`) на указателе `*Machine`.
- `Stock`: мутабельные `Add`/`Set`/`Deduct` на `*Stock`; читающие `GetAll`/`IsEnough`/`Save` по значению.
- Поле `stock Storage` — интерфейс, держит `*Stock`.
- Склад загружается при старте из `stock.txt`; при ошибке чтения создаётся новый склад.
- Сохранение только по команде `exit`.

## Бизнес-логика `Brew`

1. Проверить, что напиток существует (как ErrDrinkNotFound).
2. Проверить, что оплата достаточна (ErrNotEnoughMoney).
3. Проверить, что ингредиентов хватает (ErrNotEnoughStock).
4. Списать ингредиенты.
5. Вернуть шаги приготовления.
6. Обновить статистику (orders, revenue).
